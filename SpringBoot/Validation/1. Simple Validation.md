- Those are the built in validation in jakarta validation.
- Use it on DTOs.
---
## Usage
### Definition
```java
@Data // important
public class EmailPasswordDto {  
  
    @NotBlank(message = "Username cannot be blank")  
    @Email(message = "Invalid email format")  
    private String email;  
  
    @NotBlank  
    @Size(min = 8, max = 25 ,message = "Password must be at between 8 to 25 characters long.")  
    private String password;  
}
```
### apply
- When ever you try to use this DTO you can apply validation.
```java
public ResponseEntityM<UserDto> createUser(@Valid @RequestBody EmailPasswordDto request){
}
```
- Now if we got EmailPasswordDto that don't pass the validation, that will raise `MethodArgumentNotValidExecption`.

## Annotations
### 1. String/Text Validations

| **Annotation**       | **Description**                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------- |
| **@NotBlank**        | Validates that the string is not null and contains at least one non-whitespace character  --> {"", " "} |
| **@NotEmpty**        | Validates that the string is not null and not empty (length > 0)                                        |
| **@Size(min, max)**  | Validates that the string length is between the specified min and max boundaries                        |
| **@Pattern(regexp)** | Validates that the string matches the specified regular expression                                      |
| **@Email**           | Validates that the string conforms to a valid email address format                                      |

### 2. Numeric Validations (Integer, Double, BigDecimal, etc.)

| **Annotation**                 | **Description**                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------------- |
| **@Min(value)**                | Validates that the numeric value is ≥ the specified minimum (long-based)                          |
| **@Max(value)**                | Validates that the numeric value is ≤ the specified maximum (long-based)                          |
| **@DecimalMin(value)**         | Validates that the numeric value is ≥ the specified decimal minimum (supports BigDecimal, String) |
| **@DecimalMax(value)**         | Validates that the numeric value is ≤ the specified decimal maximum (supports BigDecimal, String) |
| **@Digits(integer, fraction)** | Validates that the number has at most the specified integer and fractional digits                 |
| **@Positive**                  | Validates that the value is strictly positive (> 0)                                               |
| **@PositiveOrZero**            | Validates that the value is positive or zero (≥ 0)                                                |
| **@Negative**                  | Validates that the value is strictly negative (< 0)                                               |
| **@NegativeOrZero**            | Validates that the value is negative or zero (≤ 0)                                                |

### 3. Date/Time Validations

| **Annotation**       | **Description**                                          |
| -------------------- | -------------------------------------------------------- |
| **@Past**            | Validates that the date/time is in the past              |
| **@PastOrPresent**   | Validates that the date/time is in the past or present   |
| **@Future**          | Validates that the date/time is in the future            |
| **@FutureOrPresent** | Validates that the date/time is in the future or present |

### 4. Boolean Validations

| **Annotation**   | **Description**                           |
| ---------------- | ----------------------------------------- |
| **@AssertTrue**  | Validates that the boolean value is true  |
| **@AssertFalse** | Validates that the boolean value is false |
### 5. Collection/Array/Map Validations

| **Annotation**      | **Description**                                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------------- |
| **@NotEmpty**       | Validates that the collection, array, or map is not null and contains at least one element        |
| **@Size(min, max)** | Validates that the collection, array, or map size is between the specified min and max boundaries |

### 6. General/Cross-Type Validations

| **Annotation** | **Description**                                                        |
| -------------- | ---------------------------------------------------------------------- |
| **@NotNull**   | Validates that the value is not null (works on any type)               |
| **@Null**      | Validates that the value is null (works on any type)                   |
| **@Valid**     | Triggers cascaded validation on associated objects (nested validation) |

### 7. Custom/Constraint Composition

| **Annotation**               | **Description**                                                                |
| ---------------------------- | ------------------------------------------------------------------------------ |
| **@ReportAsSingleViolation** | Used in composed constraints to report only the top-level constraint violation |
| **@Constraint(validatedBy)** | Meta-annotation used to create custom validation constraints                   |
| **@Target**                  | Specifies where the custom constraint can be applied (field, method, etc.)     |
| **@Retention**               | Specifies how long the custom constraint annotation is retained                |

- Use it when Derived queries become too long and hard to read, that happen when the query is too complex.
- For `@Query` you can provide `SQL` or `JPQL` "java persistence query language".
	- use sql only when there is database optimization can be used. we need to use `nativeQuery = true` to tell spring we are using SQL queries.
	- But for the most cases use JPQL because it more generic and itsn't database specific. By default **JPQL** is used.

### JPQL
- Instead of using database tables, we are dealing with entities.
- You can do joins too.
- you can update data also but **keep attention**, 
	- you should add `@Modifying` annotation before update query to tell spring that this query is update operation not select operation. 
	- You should call update query in `@Transactional` method.
```java
// find products whose price are in a give range and sort by name
@Query("SELECT p from Product p where p.price between :min and :max order by p.name")  
List<User> findProducts(@Param("min") BigDecimal min, @Param("max")BigDecimal max);
```

#### update
```java
// NOTE: We should c
@Query("update Product p set p.price = :newPrice where p.category.Id= :categoryId")  
void updatePriceByCategory(@Param("newPrice")BigDecimal newPrice, @Param("categoryId") Byte categoryId);
```

### SQL
```java
// find products whose price are in a give range and sort by name
@Query(value = "Select * FROM  products p where p.price between :min and :max order by p.name", nativeQuery = true)  
List<User> findProducts(@Param("min") BigDecimal min, @Param("max")BigDecimal max);
```

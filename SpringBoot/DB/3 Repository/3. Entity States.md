An entity goes throw different states:
- `Transient`: When we create new entity using new keyword it will be in Temporary state.
- `Persistent`: When we call `save()` method of repository that enitty get stored in database and this entity is added to container called `persistence context` "It like working memory for hibernate like applicatoinContext for beans" this context is for objects that should be tracked and managed by hibernate. This `Persistence context` has a lifetime and won't save the entity forever in memory, So when java is done with is entity it will be `Detached`
- `Detatched`: When the entity is no longer managed by hibernate but it still exists in database "which has database identifier". But when we make change at this entity and call `save()` again it will be `Persistent` again.
- `Removed`: When we call `delete()` method, the entity is become in `Removed` state and hibernate delete it from database, then it become in `Transient` state again.

- When we are dealing with database, We should know if objects we have retrieved or created are still in memory "`Persistence Context`" to do operation with it.
- The lifetime of persistence context depend on `Transaction`.

---
### Transaction
- In general a transaction is a group of operations that succeed or fail togather.
- Methods like `save()`, `delete()`, `find()` those are transacional methods, which mean when we start one of those method we start a transaction and we finish it finish the transaction. So if we have `transaction 1` and `transaction 2` we can't access entities in `transaction 1` from `transaction 2` because our `Persistence context` is per transaction .
```java
public static void main(){
	var user = userRepository.findById(1L).orElse(null); // tranaction 1
	userRepository.delete(user);// transaction 2, This can't access  user entity. EXCEPTION
}
```
- To extend our transaction boundary we will define a non-static method, which will keep our `Persistence context` open until we finish from this method:
	- Now `Transaction 2` can access `Transaction 1` entites.
```java
@Transactional // This force the persistence context open for multiple methods.
public class UserService {  
    private final UserRepository userRepository;  
	  
    public UserService(UserRepository userRepositories){  
        this.userRepository = userRepositories;  
    }  
	@Transactional // you can apply it to single method too.
    public void operations(){  
        var user = userRepository.findById(1L).orElse(null); // Transaction 1
        userRepository.delete(user);  // Transaction 2
    }  
}
```


> [!Error]
> I have tried to do delete then save in the same `persistence context` but this will generate error, because the entity won't go to transient state unless the entity is deleted and the transaction has ended, to do so you should start new persistence context. Otherwise, you can do save then delete.

- The relationship owner is reference to the foreign key, so in owner you will use `@ManyToOne @JoinColumn(name = 'DataBaseColumnForeignKey')`, and on the other end we will use  `@OneToMany(mappedBy = "JavaFieldNameInOtherClass")`

```java
// We have one-to-many relationship between user and address. 
// where the user has many addresses.
// Each address belong to one and only one user.

@ManyToOne  
@JoinColumn(name = "user_id")  //instead of column, we treat foreign key with JoinColumn.
private User user;


__User__

@OneToMany(mappedBy = "user")  
private Set<Address> addresses = new HashSet<>();

__Main___

var user = User.builder()  
       .username("slom")

       .build();  
  
user.getAddresses().add(address);  // We should always wire the 2 objects with each other. So its better to put this as method in User class
address.setUser(user);
```

#### When you DO NOT use `@JoinColumn`
- If you leave it out, JPA follows a **"Convention over Configuration"** rule. It will automatically assume the foreign key column name is: `[Name of the Relationship Field] + "_" + [Name of the Primary Key Column of the Target]`
- **The Risk:** If your database column is actually named `customer_id` or just `user`, JPA will throw an "Unknown Column" error because its "guess" was wrong.
```java
@ManyToOne private User user; // JPA looks for a column named "user_id"
```
- You should use it in almost every real-world scenario to ensure your Java code exactly matches your SQL schema.

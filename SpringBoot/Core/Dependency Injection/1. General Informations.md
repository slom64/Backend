- This help us to inject dependencies automatically without the need to put `new` keyword. This comes very beneficial in unit testing, which makes creating the dependent on objects very easy.
	- Example: `var x = OrderService(new PayPalPaymentService(new Person(new Checkout)))`. this become tedious and risk of error. 
- Spring can create objects and inject them to our class automatically. To do so, Spring uses **IoC container** this container is responsable for managing objects in our application. Those manged objects called `beans` which is regulare java object that spring take care for creating it and manage its life cycle
	- IoC "Inversion of Control", we invert managing and creating objects to spring instead of manual
	- We use `ApplicationContext context = SpringApplication.run(DemoApplication.class, args);`, which return application context which is our **IoC container** that contains the managed objects.
	- You can use `ConfigurableApplicationContext context = SpringApplication.run(DemoApplication.class, args);`. It inherit from `ApplicationContext`. which give us the ability to close, destroy context.
- You can create dependency via:
	- `Constructor`: Use this if the dependent on object is **vital** and not optional, So every object in the primary class should have the dependent on object in it.
	- `Setters`: Use this when the dependent on object is optional.
- Spring does not inject `restTemplate` unless:
	- You use constructor injection `@AllArgsConstructor`
	- OR you annotate it with `@Autowired`, if the field isn't in constructor then you have to annotate it with `@Autowired` to tell spring to inject dependencies. "**Not Recommended** to use this approch. To avoid it use `@AllArgsConstructor` so you can do dependency injection via **constructor**"

### Lazy Initialization
- By default, Spring goes to every manged bean "`@Component`, `@Service`" and runs its construct which create an object. Even if we didn't use this class in our main code, spring will create the object and we won't use it. This is the `eager` behaviour, you can change it by using `@Lazy`.
- When the class is marked as **lazy** it will be created only when we want.
```java
// Using @Configuration class
@Bean
@Lazy
public HeavyResource heavyResource(){
	System.out.println("Lazy Initialization")
}

//_____________________________
// Direct Use on class it self.
@Component
@Lazy
public class HeavyResource(){
	public HeavyResource(){
		System.out.println("Lazy initialization");
	}
}
```

### Bean Scope
Are beans created once and reused, or are they created every time we need them?
Bean scope is used to determine how and when a bean is created in spring IoC  container, the types are:
- `Singleton`: The default one, only one instance of the bean is created ber container. This is useful for stateless, reusable objects.
- `Prototype`:A new instance of a bean object is created everytime it is request from IoC container. useful for objects that have states or used temporary.
- `Request`: A new instance of a bean object is created for each http request. And the bean get destoryed when we finish processing the request.
- `Session`: A new bean instance is created for each http session. So the bean exist in duration of a session and get destroyed when the session ends.

```java
@Bean  
@Scope("prototype")
public NotificationService emailNotificationServiceBean(){  
	return new EmailNotificationService();  
}  
```

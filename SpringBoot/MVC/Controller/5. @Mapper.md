- It mainly convert/map from class object to another class object, and it used to map from entity to DTO and vice versa. It have 2 approches:
	- create new target object then assign its values using setters, and get the values from getters of the source object. `User toEntity(UserDTO userDto)`
	- update existing object `void update(UserDto userDto, @MappingTarget User user);`
	- Example `user.setName(userDto.getName)...` which repeat this for all other fields.
- Sometimes we prefer Maintainability over Performance, Mapper will load the entity or DTO as a whole from the database, but will filter out unnecessary columns from code it self.
- We will use `MapStruct`
- This Mapper interface will generate the code in compiler time and filter unnecessary columns.
	- It can convert from DTO to entity and vice versa.
- If field names in User entity don't match the names in UserDto, then use `@Mapping(source = 'FieldNameInEntity' , target = 'NameInDTO')`
	- You can assign value to target DTO even if its not represented in source, by using `expression` which generate value and you can use it if you defined the target field in DTO
	  `@Mapping(target = "createdAt", expression = "java(java.time.localDataTime.now())")`, there should be createdAt field in the DTO.

---
### Steps
1. Create DTO that contains the wanted columns, should contain `@Setter`, `@Getter`.
2. We create interface and annotate it with `@Mapper(componentModel = "spring")` , we sit componentModel to tell spring to create beans.
```java
@Mapper(componentModel = "spring")  
public interface UserMapper {
	
	@Mapping(source = "name" , target = "name") // optional, Use it when field names in DTO is different than entity fields.
    UserDto toDto(User user);
    
    // or direct
    List<UserDto> usersToDtos(List<UserDto> users);
    
    User toEntity(UserDTO userDto)
    
    void update(UserDto userDto, @MappingTarget User user);
}
```
3. use it as following
```java
@RequestMapping("/")  
public List<UserDto> getAllUsers(){  
    return userRepository.findAll().stream()  
            .map(user -> userMapper.userToDto(user))  
            .toList(); 
	// or 
	return userMapper.usersToDto(userRepository.findAll());  
}
```

### Differences

#### @MappingTarget vs Direct
> [!Question]
> what is the difference between those 2 mappings.
> `User user(UserDto userDto);`
> `void update(UserDto userDto, @MappingTarget User`
> Both of them map from UserDto to User.

##### 1. `User user(UserDto userDto);`

**The "Factory" Mapping**
This tells MapStruct: _"Take this DTO and build me a brand new User object from scratch."_
- **Behavior:** MapStruct calls `new User()`, then uses the setters to fill in the data from the DTO.
- **Result:** You get a **transient** (new) instance.
- **Use Case:** Registration or "Create" operations. Since it's a new object, JPA will treat it as a new row in the database when you call `repository.save(user)`.
- **Risk:** If you use this for an update, you might accidentally overwrite an existing record with `null` values for any fields missing in the DTO, or lose tracked entity state (like internal JPA versions).

##### 2. `void update(UserDto userDto, @MappingTarget User user);`

**The "Patch" Mapping**
This tells MapStruct: _"Take this existing User I already have and overwrite its fields using the data from this DTO."_
- **Behavior:** MapStruct does **not** call `new User()`. It takes the object you passed in the second parameter and calls `user.setName(...)`, `user.setEmail(...)`, etc., using the DTO as the source.
- **Result:** The **original** instance is modified.
- **Use Case:** Update or "Edit" operations. You usually fetch the user from the database first, then "pour" the DTO data into it.
- **Benefit:** Since the `User` was fetched from the DB, it is already **managed** by Hibernate/JPA. Any changes you make via the mapper are automatically tracked.

##### Comparison Table

| **Feature**       | **User user(UserDto)** | **void update(..., @MappingTarget User)** |
| ----------------- | ---------------------- | ----------------------------------------- |
| **Instantiation** | Creates `new User()`   | Uses **existing** `User` instance         |
| **Memory**        | Two separate objects   | One object modified in-place              |
| **JPA State**     | Transient (New)        | Usually Persistent (Existing)             |
| **Standard Use**  | **POST** (Create)      | **PUT/PATCH** (Update)                    |

##### Example

Notice how much cleaner the `@MappingTarget` version makes your update logic:
```java
public void updateUserName(Long id, UserDto dto) {
    // 1. Get the existing "live" entity from DB
    User existingUser = userRepository.findById(id).orElseThrow();
    
    // 2. MapStruct updates the "live" entity fields
    userMapper.update(dto, existingUser);
    
    // 3. Save (JPA will only update the changed columns)
    userRepository.save(existingUser);
}
```

If you used the first method (`userMapper.userToEntity(dto)`), you would have a brand new object. If that DTO didn't include the `password` or `id`, you would accidentally save a user with a null password or create a duplicate user!

Every maven project has the following built-in LifeCycles:
- default
	- LifeCycle handle compiling, packaging, and deployment of maven project.
- clean: LifeCycle handles deletion of temporary files and generated artifcates from the target directory.
	- pre-clean: if you want to attach code to be ran before start cleaning
	- clean: remove files generate from previous build.
	- post-clean: Execute processes needed to finalize the project cleaning.
- site
	- handles generation of documentation and site generation.

---

### Clean LifeCycle
LifeCycle handles deletion of temporary files and generated artifcates from the target directory.

it contain those phases:
- pre-clean: if you want to attach code to be ran before start cleaning
- clean: remove files generate from previous build.
- post-clean: Execute processes needed to finalize the project cleaning.

Clean LifeCycle is associated with `maven-clean-plugin` which contain 2 goals
- `help`: show documentation about the plugin
- `clean`: clean goal is connected with clean phase in lifecycle.

Steps:
1. We start with `pre-clean` phase, which we check if there is any plugin or code associated with it, if not its marked as completed.
2. clean phase which is connected with clean goal in `maven-clean-plugin`, so it execute this goal. the goal contain the actual instruction and code to delete file.
3. if there is no post-clean connected with plugin, then we have finished.

### Site LifeCycle
- pre-site: execute processes before the acutal project site generation.
- site: generate website that contains the site documentation.
- post-site: execute procceses after site generation.
- site-deploy: deploy the generated site documenation to specific server.

Site LifeCycle is binded to `maven-site-plugin`, which contain 2 goals:
- `site`: this goal is associated to `site phase` in site life cycle.
- `deploy`: this goal is associated to `site deploy` in site life cycle.

---
### default LifeCycle
The most important lifecycle which is responsable for compilation proccess. and contain the following phases:
- `validate`: check the project is correct and all dependancies are downloaded.
- `compile`: compiles source code.
- `test`: runs unit testing using frameworks.
- `package`: Assembles compiled code into distributable format, Ex. jar.
- `install`: installes the packaged archive into local repository
- `deploy`: push the built archive to a remote repository.

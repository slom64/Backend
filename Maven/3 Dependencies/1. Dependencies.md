- Previously, If you wanted to add external library you should download it and but it execution path manually, and sometimes this is hard if there is multiple versions from a library.
- To access specific dependency we need:
	- groupId: organization that has built it.
	- artifactId: Name of the artifact, this should be unqiue in the same organization.
	- version:
	- type: optional. filetype, JAR, WAR, POM
	- scope: optional. Some dependencies we don't need them in production like dependencies used for testing, and some of them we need them only for compiling and so on.
		- `compile`: dependecies are used in all phases. `compile` + `runtime`. "This is the default scope"
		- `provided`: dependecies will be provided to the application externally while runtime. Ex, `javax.servlet` it will be downloaded externaly from my application in production but my application use it, so there is no need to bundle it inside my app. this scope provide dependencies in `build`, `test` phases which is `compile` time.
		- `runtime`: Dep are not available in class path during build phase, instead they get bundled in the generated artifacte and they are available during `runtime`. 
		  EX. JDBC, while compiling you don't need the actual drivers "implementation" of JDBC, but you need them in runtime.
		- `test`: Dep that available during test phase. Ex, TestNG. which is used in `compile, runtime of tests only`, not for production.
		  so any dep will be accessible inside `test` folder and unaccessible in `main` folder. 
		- `system`: hard-coded dependancies that exists on disk. `<scope>system</scope> <systemPath>/home/slom/abc.jar<systemPath>` . "Bad Practice"
		- `import`: This is applicable only for `.pom` files, which import other pre-made pom files.

```xml
  <dependencies>
    <dependency>
      <groupId></groupId>
      <artifactId></artifactId>
      <version></version>
      <type></type>
      <systemPath></systemPath>
      <scope></scope>
	  <exclusions> <!-- exclude specific dependency from this dependency -->
		  <exclusion>  
		  <groupId>org.hamcrest</groupId>
		  <artifcatId>hamcrest</artifcatId>
		  </exclusion>
	  </exclusions>    
    </dependency>
  </dependencies>
```

- By default, maven will check maven central repository. if you want to get artifact from other repository, you can add it in `<repositories></repositories>`
- Transitive dependencies are the dependencies that are used by the direct imported dependency. Ex, `junit` use `hamcrest` dependency.

## Plugins overview
- maven is in general, plugin execution framework. its built on executing goals of plugins.
- we have 2 types of plugins: `build plugins`, `reporting plugins`.
- maven developers can name their plugins as `maven-${prefix}-plugin` so when we want to use the plugin we ise the middle name Example `maven-compiler-plugin` which will be used using `maven compiler:goal`, but if any other developer wants to make plugin, he should name it as `${prefix}-maven-plugin` so when we want to execute it we use the first name. Ex. `exec-maven-plugin` which will be used as `maven exec:java`. or for both cases you can use the full plugin name. `maven-compiler-plugin:compile`

---
## Plugin skeleton
```xml
<plugin>
	<groupId></groupId>
	<artifactId></artifactId>
	<executions></executions>
	<configuration></configuration>
	<extensions></extensions>
	<dependencies></dependencies>
	<inherited></inherited>
</plugin>
```
- `executions`: Used bind the plugin to specific phase in the lifeCycle.
- `configuration`: Some plugins need specific configuration to run properly. Like `exec-maven-plugin` we configure`<mainClass>gov.iti.jets.App</mainClass>`.
- `exetensions`: adds exetesions above the default build life cycle so we can have more phases.
- `dependencies`: some plugins need dependencies to run, like if plugin need to interact with database.
- `inherited`: enable or disable inheritance of plugin to child projects.

---
### executions
- When developing plugins, the goals can have a default phase binding.
- If the goal has a default phase binding, then it will execute in that phase.
- But if the goal is not bound to any lifecycle phase, then it simply won't be executed during the build lifecycle.
- Specifying Goal-to-phase binding overrides the defaults.
- **There maybe mulitple** `<execution>`, **which mean we will run our plugin or goal in different phases** ("compile then test"). which will have different configurations.
```xml
<groupId>org.codehaus.mojo</groupId>  
<artifactId>exec-maven-plugin</artifactId>  
<version>3.1.0</version>
<executions>
  <execution>
	<phase>compile</phase>
	<goals>
		<goal>java</goal> <!-- automatically do exec:java every time we are in comiple phase. -->
	</goals>
  </execution>
</executions>
```

### configuration
- `<configuration>` elements are mapped to specific fields or setters inside the plugin code.
- Example, Mojo might look like the following:
```java
public class MyQueryMojo extends AbstractMojo
{
	@Parameter(property = "query.url" , required=true)
	private String url;
	
	@Parameter(property = "timeout", required=false, defaultValue = "50")
	private int timeout;
	
	@Paramter(property = "options")
	private String[] options;
}
```

So if we want to pass a value for`url` variable or pass an array, we should pass it as follows:
```xml
<configuration>  
  <query.url>https://slom.com</query.url>  
  <options>
	  <option>One</option>
	  <option>Two</option>
	  <option>Three</option>
  </options>
</configuration>
```

to pass the parameters from command line:
```sh
-D query.url=https://slom.com
```

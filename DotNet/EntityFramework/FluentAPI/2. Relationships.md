- You can start from any end "one-to-many" so if we have relation between type1 and type2
	- `HasMany()`: if type1 has many objects of type2
	- `HasRequired()`: if type1 has only object of type2
	- `HasOptional()`: if type1 has 0 or 1 object of type2
	- Don't forget to use `WithMany()`, `WithRequired()`, `WithOptional()`. To configure the other entity relationship.
### Best Practice Rules
1. **Always define the foreign key in the "many" side** (`Course.AuthorId`).
    - EF needs a clear FK to generate proper database columns.
2. **Navigation properties on both sides** are optional, but recommended.
    - `Author.Courses` lets you query all courses for an author.
    - `Course.Author` lets you query the author of a course.
3. **Fluent API configuration can be written in either entity**.
    - Typically, people start from the **principal entity** (Author → Courses). (1 → Many).


### For relationships, you typically define:

#### On the **dependent side (the “many” side)**
- This is the **mandatory + recommended combination**
```c#
public int WriterId { get; set; }   // FK  
public Author Author { get; set; }  // navigation
```
#### On the **principal side (the “one” side)**
- This is **optional but recommended**
```c#
public IList<Course> Courses { get; set; }
```
#### FluentAPI
```csharp
builder.HasOne(c => c.Author)  
.WithMany(a => a.Courses)  
.HasForeignKey(c => c.WriterId); // now EF understand that WriterId is FK for table Author
```


---
### One-To-Many
1 Author --> Many Course
```csharp
builder.HasMany(a => a.Courses)       // Author -> many Courses
	.WithOne(c => c.Author)       // Each Course -> one Author
	.HasForeignKey(c => c.Author) // FK column in Course table
	.OnDelete(DeleteBehavior.Cascade); // Optional: cascade delete
```

---
### Many-To-Many
Course --> tag
```csharp
builder.HasMany(c => c.Tags)
	.WithMany(t => t.Courses)
	.UsingEntity(j => j.ToTable("CourseTag"));
```

---
### One-To-One

> [!NOTE]
> Not like other relationships, here you should define which part has the foreign key.

- If the one-to-one relationship is optional there is option `HashOptional()`
```csharp
builder.HasOne(p => p.Order)
    .WithOne(o => o.Transaction)
    .HasForeignKey<PaymentTransaction>(o => o.OrderId);
```
